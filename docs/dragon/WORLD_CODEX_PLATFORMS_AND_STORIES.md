# Dragon World Codex: 128 systems, 256 levels, delayed routes, original media grammar and hardware delivery

Implementation: October 2026, Skeleton Dragon original game-production branch.

**Implemented now:** typed world-state runtime, reversible design addressing,
original narrative choices, primary and optional route-gate planners,
platform-bounded generated room chunks, a mobile Forge editor, and
an original playable C99 desktop terminal-game source emitter.

**Not claimed:** Every possible game has been rendered, played, independently
verified as creatively unique, cleared of third-party IP, compiled for every
console, or validated on physical hardware.

## 1. Worlds need not be winnable to be valid

Dragon supports constructive puzzle worlds with provable completion, and
independently, worlds with no mandatory ending: sandbox, ecology, survival,
settlements, time loops, multi-realm travel, shifting maze and postgame.
Narrative conclusions can occur while the environment remains playable.

A temporarily or permanently locked optional passage does not invalidate
the world. Likewise, a formally complete story does not automatically
terminate the player, reset saved settlements, or delete other alternatives.

## 2. Sixteen world disciplines with eight axes each

Every source parameter is independently editable from 0 to 255.

| Discipline | Interacting world parameters |
|---|---|
| Geology | Tectonics, migration, caverns, volcanic activity, erosion, minerals, gravity, substrate |
| Hydrology | Ocean depths, tides, rivers, groundwater, floods, ice, currents, water purity |
| Climate | Storms, rain, wind, sunlight, snow, heat, fog, atmospheric pressure |
| Ecology | Flora, migrations, predators, pollination, disease, restoration, regrowth, habitats |
| Settlements | Urbanization, decay, reconstruction, housing, transit, services, food, migration |
| Factions | Trust, diplomacy, territory, reputation, alliances, espionage, mobility, autonomy |
| Economy | Price cycles, material scarcity, barter, logistics, tolls, crafting, labor, informal trade |
| Technology | Research, engineering, power grids, automation, communication, repair, manufacture, diffusion |
| Arcana | Rituals, flow, portals, fatigue, enchantment decay, turbulence, countermagic, dream gates |
| Cosmology | Orbits, alignment, radiation, distances, shuttle infrastructure, time dilation, dimensional travel, contact |
| Narrative | Consequential choices, story branches, ambiguity, delayed clues, reliability, endings, loyalty, history |
| Chronology | Eras, drift, aging, access to past/future, time anomalies, resets, generations |
| Topology | Changing mazes, rotating rooms, one-way paths, secrets, doublebacks, scenic routes, height, seams |
| Traversal | Ground friction, boats, aerial navigation, train schedules, airships, caravans, fuel, shortcuts |
| Access | Skill gates, equipment, social permission, time, climate, resource and knowledge locks |
| Postgame | Repopulation, rebuilding, inherited progress, alternate endings, frontier expansion, dynasties, ecology, scars |

The 128 parameters fit a reversible 128-byte/1024-bit integer. The source
address is a canonical arbitrary-precision decimal string. Each older
base design can be combined with exactly 256 raised to the power 128 Codex
genomes, far beyond a quintillion distinct address values.

All addresses are generator configurations, not finished unique games.

## 3. Actual player state and environmental effects

A player studies chosen axes, advances the world clock, develops domain
reputation, earns world-era milestones and discovers real conditional
passages. Each action receives a deterministic gameplay-history digest.
Every domain changes its generated environmental signal, including hazard
and resource supply; game-state and passage constraints consume those
signals. World editing produces a new explicit source identity.

The world has no universal compulsory victory requirement.

## 4. Deep delayed access and branching travel

Primary route plane: sixteen actual travel classes, including cavern
depths, tidal transport, storm paths, wildlife migration, urban bridges,
diplomatic corridors, merchant routes, research lifts, dream passages,
orbital lanes, story revelations, ancient eras, rotating mazes, intermodal
travel, secrets and postgame frontier expansions.

Each primary route requires **two trained parameters**, a minimum turn
and a periodic window. The builder constructs actual training, waiting
and traversal steps and independently replays the resulting journey.

Second route plane: 128 additional conditional optional gates (one per
axis). Each gate can require mastery, companion knowledge, a specific
seasonal phase, a time window and earned historical eras. It may be
unavailable within a search horizon while the world remains perfectly
playable. Status distinguishes not-yet-earned, calendar closed,
historically locked and reachable now. Search says NOT PROVEN within
the horizon, never globally unsolvable without exhaustive proof.

The system supports long doublebacks and inefficient scenic choices
from prior Dragon route construction; Codex access is an added layer
rather than a forced replacement.

## 5. Original story grammar inspired by media design principles

Games suggest real player agency and consequential choices. Film offers
temporal juxtaposition, scope contrast and multiple viewpoints.
Literature offers unreliable evidence, generational histories,
ethical ambiguity and interior perspectives.

The Codex combines 64 original setting concepts with sixteen conflict
archetypes, eight perspectives, eight chronology structures and eight
staging approaches. These are broad ideas, not copied commercial plots.

Actual narrative actions include investigating, helping rival groups,
negotiating, preserving or concealing evidence, exploration,
reconstruction, completing a chapter and choosing optional aftermaths.

A high revelation-delay setting cannot complete a story chapter without
enough real world time and study. Decisions change actual allegiance and
future endings. Completing a chapter does not end the game universe.

Never include commercial story dialogue, character appearances,
recognizable franchise titles, proprietary maps, film scenes or
unlicensed novel text in original deliverable game content.

## 6. Platform-aware content must reflect real device constraints

Dragon reads CPU, graphics, sound, input, native toolchain, output type,
maximum registered color count and nominal output resolution from its
actual native target catalog.

Content cohorts are conservative design bounds rather than measured
hardware RAM or guaranteed frame-rate performance.

| Hardware cohort | Live domains | Axes/domain | Quantized levels | Rooms/chunk |
|---|---:|---:|---:|---:|
| Early scanline systems | 4 | 4 | 8 | 8 |
| Cartridge 8-bit | 6 | 4 | 8 | 12 |
| Home 8-bit micros | 6 | 4 | 8 | 12 |
| 16-bit home/arcade | 8 | 6 | 16 | 24 |
| Early polygon 3D | 8 | 8 | 32 | 32 |
| Portable 3D | 8 | 7 | 32 | 32 |
| Sixth generation | 10 | 8 | 64 | 48 |
| Seventh generation | 10 | 10 | 96 | 64 |
| Modern console | 12 | 12 | 128 | 96 |
| Desktop/portable PC | 16 | 12 | 128 | 128 |
| Browser/mobile | 12 | 10 | 96 | 64 |
| Other/experimental | 6 | 5 | 12 | 12 |

Each registered target receives a deterministic original data plan with
actual quantized values, deferred-feature inventory, game route
selection, source chunk IDs and an independently regenerable content
digest. These **are not** compiled console ROMs or proprietary SDK ports.

Use separate levels of release evidence:

1. Source design: world rules and original content independently reproduced
2. Platform content: actual bounded room/progression data generated
3. Toolchain project: dedicated native source/asset/loader runtime
4. Compiled binary: toolchain actually completed on a known architecture
5. Device verification: real controller, timing, visuals, saving and
   legal distribution requirements actually checked

The current generic Codex cartridge adapter supplies level 2.
No claim of state 3-5 is made without real toolchain/device evidence.

## 7. Native desktop game deliverable

A distinct C99 emitter produces original interactive game source
with all 128 study skills, 16 earned temporal gates, player coordinates,
world clock, era progression, free exploration, status/map commands
and no final boss requirement.

The program implements a 16-gateway internal selftest. Game source
is accessible through the authenticated Codex API and the mobile
Forge can export it for compilation.

Typical compatible local host commands:

    cc -std=c99 -O2 -Wall -Wextra dragon_codex_game.c -o dragon_codex
    ./dragon_codex --selftest
    ./dragon_codex

Source availability alone does not mean the current PR's executable
has already passed compilation or been tested on a console.

## 9. Research inspiration and lawful source boundaries

Tiled's rule-based automapping and infinite maps demonstrate why source
world constraints should be distinct from authored tile layouts:
https://doc.mapeditor.org/en/latest/manual/automapping/
https://docs.mapeditor.org/en/stable/

GB Studio documents different Game Boy color modes and compatible
hardware, illustrating why platform conversion is more than recoloring:
https://www.gbstudio.dev/docs/settings/

Research can inform *ideas* and general authoring architecture. Do not
copy proprietary games, film/book expression, ROMs, commercial artwork,
audio, dialogue, characters or platform signing secrets.
