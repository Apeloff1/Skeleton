# Studio D — First playable delivery acceptance

This source-level, POSIX-only end-to-end acceptance path joins the canonical original game builder to a deterministic offline ZIP, no-clobber private installation, actual interactive moves, private hash-chained save, independent restore, and triple-custody delivery assurance. It does not call an external model or network and does not qualify a native Godot executable, Windows device, malware posture, rights, signing or release.

Build original source with the existing \`python -m skeleton app studio-journey --onboard ... --output ... --trusted-local-operator\`. Retain the independently obtained SHA-256 of \`release.json\` outside the game directory.

Then run \`python -m skeleton app first-playable-delivery --source ORIGINAL --archive NEW.zip --install NEW_INSTALL --save NEW_SAVE.json --receipt NEW_RECEIPT.json --expected-manifest-sha256 PIN --moves up,right,down --trusted-local-operator\`. All four outputs must be new and disjoint from both game trees, with owner-controlled parents. A single command runs real source verification, archive publication, installation, gameplay, save, restored replay and cross-component assurance. It returns four independent pins; retain them outside the installation and receipt.

Reinspect the live installation and private replay with \`python -m skeleton app first-playable-delivery --inspect --archive ZIP --install INSTALLED --save SAVE.json --receipt RECEIPT.json --expected-manifest-sha256 MANIFEST_PIN --expected-archive-sha256 ARCHIVE_PIN --expected-save-sha256 SAVE_PIN --expected-receipt-sha256 RECEIPT_PIN --trusted-local-operator\`. Inspection performs fresh full source/ZIP/save replay and verifies the historical receipt against the four externally held digests.

Any failure after an output is published leaves that output in place for explicit quarantine. Never automatically delete a partially installed tree or reuse a published filename. Preflight is not a reservation; every writer repeats atomic no-clobber checks. The handoff receipt is integrity-pinned but unsigned and does not supply monotonic rollback custody. Exact-head tests and security gates, actual native hardware, rights and release qualification remain separate requirements.

The original source is reverified after handoff publication as well as before it. A failure after the final receipt hardlink is **durability uncertain**, not safe to roll back: published receipts, archives, saves and partial installs must be quarantined by the owner. Private-save publication follows the same no-unlink-after-link rule as receipts and archives.
