# Independent exact-policy reviewer deployment

This source candidate is a conservative independent review queue, not a
semantic prompt-injection detector. It signs **allow only for exact UTF-8
context digests independently approved in advance**. New conversations and
changed history require new approval. The v1 review digest covers the
existing client protocol's untrusted text projection, not an independent
per-role, per-actor or per-request authorization. Canonical snapshot and
execution attestation separately bind the actual actor and writer epoch.
Do not mistake content approval for tenant access authorization.

## Trust separation

Deploy on a separately administered host, user, private filesystem and
network segment, never alongside model-writable files or the application
Mongo volume. The reviewer needs only Python 3.11+, cryptography, the two
scripts, its own dedicated TLS certificate/key and independently approved
client CA, and its own Ed25519 private key. The application holds the public
Ed25519 anchor, server CA, and an independently issued client certificate
and key. The private reviewer key never enters application configuration,
source control, image layers or execution receipts. Mount reviewed files
read-only, with private key files owned by the service account and mode 0600.
The server listens at the explicitly supplied IPv4 address; restrict firewall
ingress to authorized application hosts. Use separate TLS CA and signer keys.

The policy is a bounded JSON object with exact fields:

    {
      "schema": "skeleton.guard.independent-exact-policy.v1",
      "authority_id": "reviewer",
      "deployment_domain": "independent-domain",
      "issued_at": 0,
      "expires_at": 0,
      "client_certificates": [],
      "approved_contexts": [],
      "challenge_scopes": []
    }

Illustrative placeholders above are intentionally invalid. Set real Unix
timestamps (maximum 24-hour validity), a nonempty set of client DER leaf
certificate SHA-256 values, independently approved exact content SHA-256
values, and one or more challenge scopes with exactly tenant_id, actor_id,
context_id, model_digest, runtime_digest, and tokenizer_digest. Do not derive
approval by blindly hashing incoming chat text. The policy file SHA-256 is
an independent operator pin. Policy and signing key changes require replacing
the process through an independently controlled deployment procedure. No
public policy mutation endpoint exists. Exhausted nonce capacity denies;
the service executable requires the durable ledger described below.

Run only from the trusted deployment checkout:

    python -m scripts.serve_independent_reviewer \
      --bind 127.0.0.1 --port 8443 \
      --policy /private/reviewer/policy.json --policy-sha256 REVIEWED_SHA256 \
      --signing-key /private/reviewer/signing.raw --signer-public-key-sha256 REVIEWED_SIGNER_PUBLIC_SHA256 \
      --tls-cert /private/reviewer/server.pem --tls-cert-sha256 REVIEWED_SERVER_PEM_SHA256 --tls-key /private/reviewer/server.key \
      --client-ca /private/reviewer/client-ca.pem --client-ca-sha256 REVIEWED_CA_PEM_SHA256 \
      --replay-database /private/reviewer/state/replay.sqlite3 \
      --replay-ledger-id INDEPENDENT_64_HEX_ID

Use a private routable address instead of loopback for a separate host.
The key is exactly 32 raw Ed25519 private bytes generated by the independent
authority. Never use a fixture key or commit a real policy or private key.
There is no unauthenticated readiness or signing endpoint. Server rejects
noncanonical challenges, repeated nonces, malformed/overlarge bodies and
missing or unpinned client certificates. Absolute connection limit,
bounded concurrent connections and response redaction apply.

On the application root use a TLS client context built with the separately
pinned CA and client certificate/key; construct SignedReviewerClient and
ReviewerTrustAnchor from independent pins. TrustedNativeStartup requires
live scoped challenge attestation at admission, before dispatch, and before
final delivery, using the durable actor and actual linearizable source epoch.
A signature proves possession and binding, not semantic safety or real
administrative independence. Default Compose remains unactivated pending
separate writer/replica deployment, independent policy and certificate
custody and physical acceptance.

The independent reviewer qualification workflow creates temporary CA, server
and client certificates, exercises real loopback mTLS and the actual client,
and tests scoped owner/epoch changes. Fixture proof does not attest production
deployment. No credentials, user text or signer keys are published.


## Pinned application TLS configuration

Trusted Linux deployment code may construct PinnedReviewerTLS with absolute
CA, client certificate and client private key files, and independent SHA-256
pins of the exact CA and client certificate PEM bytes. Then call
create_pinned_reviewer_client with the independently reviewed HTTPS endpoint
and ReviewerTrustAnchor. The client uses only that CA inventory, hostname
validation, TLS 1.2 or newer, no environment proxy trust and sealed ephemeral
Linux descriptors for loading the cert/private key into OpenSSL. Unsupported
hosts or missing descriptor sealing fail closed; no plaintext fallback and
no temporary private key copy. Memory/swap inspection, filesystem ancestor
trust and host administration remain independent controls. TLS private key
ownership and mode must be verified; the signing private key belongs only
to the separate reviewer host.

## Durable nonce custody

Independently create a private state directory (0700) and a random 64-hex
ledger identity, then initialize it once:

    python -m scripts.independent_reviewer_replay --initialize-new-ledger --database /private/reviewer/state/replay.sqlite3 --ledger-id INDEPENDENT_64_HEX_ID --authority reviewer --domain independent-domain --capacity 1000000

The signer CLI requires this already initialized ledger and rejects absent,
foreign or exhausted custody. Atomic SQLite transactions consume nonces before
signing; policy or key rotation does not reset the ledger. No context bytes
or raw nonce stored. Keep the ledger on private persistent local storage,
with independently reviewed backup and rollback prevention. Restoring an old
copy can restore old nonce state; physical rollback protection and filesystem
administration are not provided. No automatic pruning or reset is allowed.

## Linux independent service candidate

The unit and invalid-until-populated operator.env.example under deploy/independent-reviewer
are opt-in installation inputs, not an installer that modifies the application or
host. Install the reviewed scripts and separate cryptography environment under
/opt/skeleton-reviewer, configure a dedicated service account, root-controlled
public pins and narrowly readable owned private keys in /etc/skeleton-reviewer,
and explicitly initialize the persistent 0700 state directory and replay ledger.
The signer public pin hashes the raw 32-byte Ed25519 public key; TLS pins hash
exact PEM bytes. --validate-only checks policy, ledger, signing key and TLS custody
without opening a listener. Runtime startup repeats the checks. The unit denies
core dumps and restricts process, resource and writable filesystem scope; network
firewall and administrative separation must be independently configured. Unit
compatibility on the target system and crash/backup recovery are unqualified.
The signed async client now enforces a true coroutine total timeout on network
review; legacy synchronous compatibility callers retain their older constraints.
