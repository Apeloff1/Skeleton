# Adversarial world-clock laboratory: real source-replayed NPC counterfactuals
**Authored:** 2026-10-13, Europe/Oslo. **Dependent:** verified interleaved game clock #3699 and portable source-only event save #3701.

## Why this is actual game-engine work
The original game builder now supports adversarial replay of up to ten alternative **complete** source-event orders against the same immutable original game sources, signed 49-cell NPC world, world settings and identical action inventory. The alternative worlds are not imagined by an LLM: each independently runs the real platformer/racing/sandbox Physics source admission, original farming/sailing/flight earned events and real NPC quest-world state machine.

## Measurable world consequences
Each successful alternate schedule gets its own verified world digest and complete measured vector: original world turns/time, player supplies, stamina, finite gold and reputation, site-specific damage and stock, started/active/expired/completed/exploited quests, per-NPC first-hand memories, rumor propagation and original physics/genre actor chronology. The laboratory shows both the absolute real results and exact deltas against the validated baseline. A real change in source ordering changes the world actor chronology, witness memories, quest causality or site resource state when those mechanics actually vary; equal final results remain measured equal rather than claimed superior.

## Source completeness and provenance
The baseline must first pass independent complete-game source verification. A candidate is executable only when its authored global ticks are contiguous and the original scheduler accepts **all true source events exactly once**. Missing achievements, source-local event inversion, a forged actor, impossible world tick, repeated physical receipt or fabricated reward fails closed. Such alternatives remain visible as rejected hypotheses with a reason and no assigned score, score improvement or source-world certification. The complete before/after evidence remains independently replayable, and a canonical SHA-256 experiment chain ties scenario inputs to their actual measured results.

## Objective metrics and fairness
Four explicitly authored finite, measurable axes are supported: preserve actual site integrity, retain finite supplies, maximize **earned** quest completions and maximize original NPC firsthand memories. Each uses only the actual verified state field. The laboratory calls the highest-scoring scenario a *favorite under the authored metric*, not an automatically superior game or intelligence improvement. A tie favors the original unchanged baseline to prevent needless changes. No automatic model-weight promotion, game publication or overwritten source project exists.

## Studio experience
Inside the original local game Studio, **Generate alternate original source event orders** proposes deterministic adjacent swaps from the already replayed baseline while preserving per-source local event order. Creators can edit up to ten bounded alternative JSON schedules, choose a real-world metric, and click **Independently replay and compare real NPC worlds**. The result shows valid versus rejected scenarios, real verified source event digests, exact per-site/NPC deltas and metric outcomes. **Select tested alternative** is a separate operator action: it writes the confirmed alternate schedule into the source clock editor only, clears earlier proof state and requires a fresh explicit complete world replay before any consequences are enacted.

## Regression and release boundaries
Ten engine adversarial tests compare real actor-order changes, omitted physical events, impossible source indices, unchanged-source immutability, deterministic proposal generation, non-synthetic metric scoring/tie policy, source time effects, malformed scenario limits, forged measurements and client-altered original game assets. Four Studio tests verify all live controls, stale-source rejection, original-world replay, no automatic adoption and separate candidate selection. Full Windows and Ubuntu reference-engine tests and pinned native Godot integrity checks are required for this PR's exact head.

Source ordering here means reviewed **event-level** interleaving, not a simultaneous lockstep multi-engine physics simulation. SHA-256 chains are reproducibility receipts, not private-key author signatures. No commercial hardware certification or automatic training-data admission.
