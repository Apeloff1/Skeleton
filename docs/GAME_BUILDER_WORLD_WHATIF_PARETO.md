# Original game world what-if laboratory: verified cross-engine causal comparisons
**Date authored:** 2026-10-12, Europe/Oslo. **Stacked on:** #3701 interleaved portable game saves, #3699 logical world event scheduler and previous native source-custodied original game engines.

## Executable counterfactual gameplay
Game creators compare between two and eight different authored schedules containing the SAME original physical incidents, genuine farming/sailing/flight achievements, and exact same multiset of real original NPC-world commands. The experimental dimension is the event ordering. The lab rejects hidden extra actions, missing incident records, duplicated achievements, changed sources and artificial rewards.

Every candidate is independently rerun through the original genre engines, physical collision proof and 49-cell NPC world. NPC location, firsthand memory, rumor spread, resource consumption, damaged site, evidence, quest and outcome are generated by canonical execution, not model imagination. Each alternate schedule must be distinct, respect its source-local order, use an actual sequential logical world clock and deliver every genuine event exactly once.

## Evidence and measurement
Each run reports a source-event chronology including original actor, event ID, original trace and physical source origin, real NPC direct witnesses, active quest IDs, time, rumor-edge counts and the final receipt/hash. The lab measures twelve explicit preference axes: original quests completed, remaining site integrity, site stock, remaining player supplies/stamina/gold, player reputation, genuine firsthand memories, total NPC trust, inverse suspicion, inverse exploited quests and survival. Extra report-only axes include active and expired quests, hearsay records, rumor edges, elapsed world ticks and source event counts.

## Fairness, tradeoffs and Pareto analysis
All candidates must have an identical multiset of source event identities and original NPC commands; the comparison does not reward adding a new cargo delivery or removing a difficult physical incident. Users may choose distinct approved objectives but cannot submit arbitrary self-reported profit, model improvement or imagined knowledge gains. A candidate strictly dominates another only when it is no worse on EVERY chosen axis and better on at least one. Alternatives with gains and losses are preserved as tradeoffs on the Pareto frontier, not forced into an unearned winner. Baseline comparisons include signed deltas for every observable metric.

## Studio controls
The authenticated local game creator includes Capture verified timeline as baseline, Derive a distinct neighboring event-order variant, Capture authored alternative, and Replay and compare the original worlds. The original event-clock JSON editor remains accessible; independent source checks run on the server. The result panel exposes the fully replayed candidate events, actual witness/quest changes, selected outcome axes, nondominated candidates, strictly baseline-dominating candidates and evidence digests.

## Security and cost bounds
Two to eight unique schedules, original finite episode/genre-source budgets, maximum 96 events per schedule and full independent replay per candidate. No interpreted arbitrary scripts, fabricated original source results, changed user saves, unattended model training, automatic publishing or native combined-world certification. SHA-256 chains provide reproducibility/content identity, not a private-key identity or author signature. This is event-level simulation, not frame-accurate simultaneous engine execution.

## Regression suite
Eleven engine tests challenge authentic alternate orders, same-source input parity, duplicated schedules, omitted source events, direct witness versus rumor distinction, maritime and aviation causal alternatives, invalid scoring axes, malformed scenario cardinality, tampered Pareto scores and source game forgeries. Three Studio tests verify working controls, exact source custody, result certification limits and independent same-origin server replay. Both Windows and Ubuntu reference tests, Native Godot Lab, PR Hygiene and secret scanning are required for merge readiness.
