# 500,000 Forge Studio operations · 100 construction volumes

**Repository owner:** Apeloff1/Skeleton · **PR:** #4200 · **Status:** source committed, exact-head end-to-end qualification pending

The Forge game-production stack contains 500 direct source producers, 4,500 original composed recipes, 45,000 gameplay-expanded recipes, and 450,000 directed production recipes. The latter are **virtual-indexed executable compositions**, not 450,000 individually handwritten engines or finished playable games.

## 100-book index

The ten original domain books live in [the source-authoring collection](../game_studio_50000/README.md). The following **90 new domain × director handbooks** give all 50 source archetypes in each domain and detail the nine production treatments and ten gameplay-layer compositions used by that director.

## High-level execution map

1. **Source:** immutable `StudioProject` authoring, original versioned game-learning workspace file.
2. **Primitive operations (500):** concrete tile, actor, environmental, quest, population and object mutators.
3. **Game recipes (4,500):** ten domains × fifty source archetypes × nine treatments.
4. **Expanded gameplay (45,000):** each recipe × ten distinct spatial/sensor game systems.
5. **Directed production (450,000):** each expanded recipe × ten independent gameplay directors (nine documented here plus `player_agency` in the full code; see note below).
6. **Catalog:** virtual 500,000-operation `AuthoringCatalogue`, with bounded indexed lookup and a 64-result maximum per discovery query.
7. **Editor:** existing Forge project CRUD, authenticated REST and React Native Jeeves editor, real source IDs, CAS persistence and native Godot source compilation.
8. **Evidence:** project digests, per-step receipts, replayable seeding and typed source roundtrips.
9. **Qualification:** exact-head CI regression and native playthrough before merge and release.

## A note on the tenth director

The built directed production engine also implements **`player_agency`** as the tenth director, creating choice paths and alternative progression. The 90-books collection uses nine named directors in each domain; `player_agency` is covered by the original domain books' choice/branching sections and must be independently tested as an executable workflow. The collection is **100 documentation volumes** (10 original domain manuals plus 90 new domain/director manuals), not 110.

## Search and authoring examples

```text
GET /api/game-frontier-authoring/recipes?generation=directed&domain=realm&director=audio_cues&offset=0&limit=32
GET /api/game-frontier-authoring/recipes?generation=directed&domain=living_story&system_layer=story_convergence&offset=0&limit=32
```

Actions have the exact form `direct_<domain>_<source>__<treatment>___<system_layer>____<director>`, and edit requests use the same `/projects/<project_id>/edits/preview` and `/projects/<project_id>/edits` handlers as the original editor. All producer subcommands are selected on the server, never injected through model-provided executable code.

## Verification boundaries

Registered command count is a feature surface measure; it **does not imply** that a separately produced game, runtime mechanic or unique low-level algorithm exists for each composite name. Game authoring changes actual typed source (tiles, environmental RPG event pages, and new quest/actor fields where applicable), but the native runtime must separately approve noncommutative world mutations and prove physics, collision, audio playback and graphical assets. The project file size is bounded by the canonical workspace's per-file quota; split longform projects into authorized source chapters as necessary.

**Tests:** `skeleton/testing/test_game_frontier_studio_production_500000.py`, plus earlier functional producer suites. **Relevant code:** `skeleton/forge/game_frontier_studio_directed_production.py`, `skeleton/forge/game_frontier_studio_authoring.py`, and the original RPG event/expedition compilers. **Acceptance:** full app E2E and native Godot smoke at the final commit, with rights and code-quality checks.
