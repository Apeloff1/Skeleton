### L04 Runtime control flow

**Implementation**
- Results bind to worker/environment/scorer identity and aggregate deterministically.
- normalize -> authorize -> reserve -> execute bounded capability -> persist/emit -> verify -> finalize receipt.

**Acceptance**
- Cancellation/deadline reaches every child operation.
- No retry/recursion/delegation/search/background loop is unbounded.

**Design invariants**
- Runtime flow is a bounded state machine with explicit terminal states, monotonic operation identity, cancellation propagation, retry budget, concurrency cap, and child-work ownership.
- A model may propose next work but deterministic orchestration owns admission, transition, side-effect dispatch, checkpoint, and finalization.

**Failure modes**
- Crash/restart resumes from durable checkpoint or reconciles ambiguity; it never guesses success from missing acknowledgements.
- Cancellation, timeout, or budget exhaustion stops descendant work and prevents new privileged I/O after terminalization.

**Telemetry & SLOs**
- operation_duration_p50_p95_p99, cancellation_latency_p95, retries_per_operation
