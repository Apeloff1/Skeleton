## Mission

Build one application containing two internal AI systems that compete over every material game artifact. The system must use iterative time as an advantage: create, attack, improve, reconcile, verify, checkpoint, and repeat until the selected effort budget is exhausted or an explicit terminal condition is reached. Local polish never outranks whole-game consistency.

The system is intentionally adversarial rather than consensus-first. One rival produces the strongest candidate it can. The other must find concrete weaknesses and submit a materially improved challenger. A deterministic arbiter applies declared hard gates and promotes only an evidence-backed champion. Roles rotate every round so neither model becomes the permanent author or permanent critic.

## Exact three-stage rival cycle

Every round has exactly three stages:

1. **Construct** — current builder produces a complete candidate from ProjectDNA, canon, authoritative project state, the current champion, and rights-classified evidence.
2. **Attack and improve** — opposing rival attacks correctness, player value, fun, originality, coherence, aesthetics, accessibility, feasibility, performance, continuity, and rights risk, then submits an improved artifact rather than critique-only prose.
3. **Reconcile and promote** — original builder may rebut, accept, or synthesize. The deterministic arbiter checks hard gates and promotes a Pareto-safe winner/synthesis. Materially different strong alternatives may remain branches.

The UI may present playful competitive banter, including laughter, but banter is never evidence and cannot replace a concrete defect, counterexample, patch, asset, scene, rule, or other improved deliverable.

## Prime directive: long-form consistency

A local improvement is invalid if it silently damages long-form consistency. Every relevant candidate is checked against ProjectDNA, GamePillars, CanonLedger, WorldStateGraph, CharacterStateTimelines, NarrativeCausalityGraph, QuestDependencyGraph, MechanicInvariantSet, VisualLanguageBible, AudioLanguageBible, ForeshadowingLedger, PayoffLedger, and ContinuityDebtLedger.

The system tracks chronology, character knowledge and motivation, geography/travel time, setup/payoff, quest prerequisites and consequences, mechanic/narrative agreement, progression, motif continuity, player-choice persistence, save/replay identity, and late-game callbacks to early facts. Contradictions block promotion unless explicitly encoded as an intentional device such as unreliable narration, branch divergence, retcon proposal, dream/simulation, or other declared project semantic.

## Atomic inspection

Every artifact can be inspected at the smallest useful unit without losing parent context:

- visual: pixel/sample → region → sprite/texture/material/mesh element → frame → shot → scene;
- narrative: token span → line → dialogue turn → beat → scene → sequence → act → character/quest/campaign arc;
- design: input → verb → rule → mechanic → state transition → encounter → mission → level → system → meta-system;
- audio: sample window → event → SFX/voice/stem → cue → mix snapshot → soundscape;
- code: expression → statement → function → component → system → module → build artifact;
- world: entity → component → relationship → location → region → faction → timeline event → world state.

Atomic QA may never sever provenance or the link back to the containing scene, story, system, project pillar, and canon revision.

## Rights, provenance, and originality

The goal is a clean-room, evidence-bearing pipeline that minimizes copyright, license, trademark, trade-dress, confidential-information, consent, and provenance risk. Software cannot guarantee “avoid all copyrights known to man” or make final legal determinations, so ambiguous cases fail closed to human/legal review.

Every source is classified before use. Supported states are project-owned, public-domain, permissive-reuse, licensed-reuse, facts-and-ideas-reference-only, restricted-reference-only, unknown-quarantine, and forbidden. Unknown is quarantined by default.

Hard rules:

- do not reproduce protected text, code, art, music, audio, characters, maps, levels, logos, or other expressive material without a compatible permission basis;
- reference-only material may inform facts, techniques, constraints, and abstract ideas, but not supply protected expression;
- preserve required license notices, attribution, and consent;
- block export when incorporated third-party provenance is missing;
- screen text, code, image, audio/music, names/marks, level layouts, and distinctive character/world elements for suspicious near-duplication;
- treat similarity scores as risk signals, not legal conclusions;
- favor first-principles solutions grounded in project-specific DNA and canon rather than imitation of named games, franchises, studios, artists, composers, writers, or codebases.
