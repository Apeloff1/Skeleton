## What “functional” means

A functional LLM/game-builder product must complete one durable end-to-end transaction: natural-language objective → governed context → provider-neutral inference → bounded rival competition → authorized project mutations → scene/simulation/presentation execution → automated playtest and continuity verification → rights/security/performance gates → reproducible build/export → close/reopen/replay/recovery.

Provider-native objects, engine-native objects, model confidence, chat history, benchmark scores, or generated prose never become execution authority.

## End-to-end acceptance spine

1. create or reopen a durable game project
2. accept a natural-language game-building objective through the provider-neutral LLM session
3. compile policy, project canon, memory, retrieval evidence, tools, budgets and model configuration into governed context
4. produce a candidate plan without granting the model execution authority
5. run dual-rival proposer/challenger/verifier competition at the selected Forge-100/1000/10000 effort tier
6. rights-screen all external references and generated assets/code/narrative before promotion
7. commit validated project/world/scene/entity/component/asset/script/narrative changes through editor transactions
8. simulate physics/gameplay and render/audio/UI paths under deterministic or tolerance-bounded contracts
9. run automated playtests, continuity checks, performance budgets, security checks and regression evaluation
10. build/export a target artifact from content-addressed governed inputs
11. bind the exported artifact to exact source, project, dependency, model, config and evidence identities
12. close and reopen the project, replay receipts, verify no duplicate side effects, then continue editing from durable state
13. demonstrate cancellation, rollback and recovery from an injected partial failure without corrupting project authority

## Dual-rival quality system

Proposer and challenger compete under equal bounded authority. An independent verifier arbitrates evidence and owns no production write capability. Forge-100, Forge-1000, and Forge-10000 change evaluation effort only. New foreground work preempts idle mirror-room improvement. Repeated no-gain hypotheses back off rather than creating unbounded loops.

## Rights and copyright clean room

External game sources are reference evidence, not copying authority. Every acquired source carries provenance and rights metadata. Generated assets/code/narrative are similarity-screened; unclear licensing or suspicious similarity quarantines the candidate. Clean-room re-expression and independent verification are required before promotion when influence is material.
