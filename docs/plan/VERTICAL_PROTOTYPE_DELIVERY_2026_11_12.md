# Complete vertical prototypes: execution brief

Priority: **Jeeves → Dragon → Skeleton**. This is the enhanced execution prompt
and delivery contract for the current prototype work. It records intent; it is
not a release certificate or a competitive superiority result.

## Enhanced prompt

Act as an accountable product, design, and engineering team. Turn the existing
verticals into exceptional, complete, working prototypes that end users can
meaningfully use. Start implementation immediately and continue through
integration, verification, and reviewable draft delivery.

Use a fresh clone of the real project. Read its architecture and construction
contracts, inspect current pull requests, and incorporate relevant compatible
work into an isolated integration branch. Preserve existing source, authorship,
security boundaries, and durable user state. Record conflicts, dependencies,
superseded fixes, and work intentionally retained outside the integration.

Prioritize Jeeves, then Dragon, then the surrounding Skeleton application.
Define each vertical by its intended user, the outcome it enables, and complete
user journeys. Infer routine implementation decisions from the existing
project. Ask only when missing information materially blocks correct work.

Pursue depth and coherence. Complete the interface, backend, data model,
persistence, validation, permissions, failure recovery, and operational setup
needed for those journeys. Expand scope when it improves a complete experience.
Choose current techniques for demonstrated user benefit, with explicit resource
budgets and recoverable behavior.

Make the experience exquisite through precision: a clear hierarchy, consistent
typography and spacing, purposeful density, accessible controls, responsive
layouts, excellent keyboard interaction, and useful feedback. Primary actions
must produce real outcomes. Address first use, return visits, loading, empty
results, invalid input, errors, retries, interruptions, and successful completion.
Keep engineering diagnostics in appropriate details and operator surfaces.

Use real application behavior and durable data. Maintain canonical ownership
for model execution, conversation history, knowledge, and source authority.
Keep demonstration fixtures distinguishable from trained models and live
integrations. Missing dependencies must produce accurate readiness and a useful
next step. Never substitute a simulated success for unavailable execution.

Work extensively in parallel with explicit file ownership and coordinated
interfaces. Integrate continuously, keep milestones reviewable, and publish
substantive draft PRs as capabilities become usable. Update drafts with the
actual implemented behavior, reproducible validation, useful screenshots, and
remaining gaps. Preserve existing PRs and default-branch release controls.

Exercise the actual product. Run appropriate automated checks and browser
journeys, inspect desktop and mobile layouts, validate persistence across
restart, and induce important failures. Fix discovered defects. Supply clear
setup, configuration, migration, backup, restore, and rollback instructions.

Compare competitors using current attributable evidence and equivalent user
tasks. Freeze versions, hardware, model, quantization, context, corpus, prompts,
network conditions, and budgets where applicable. Measure completion, quality,
citations, latency, resource use, accessibility, and recovery. Separate observed
results, vendor claims, and untested assumptions. Report an advantage only for
the workflows and conditions the evidence supports. Continue factual progress
updates without declaring superiority prematurely.

Deliver links to drafts, working journeys, executable evidence, setup notes,
and material limitations. Distinguish a working prototype, source qualification,
production device qualification, and independently verified competitive results.

## End-user acceptance

### Jeeves

An owner can connect to the authenticated local workspace, understand model
readiness, create and organize conversations, obtain an actual local model
response, inspect source-scoped context, reopen saved history, and export or
restore it. Interruptions, context limits, contention, and invalid imports
preserve existing history and give an explicit recovery path.

The current increment adds durable conversation titles, pins, and archives;
metadata uses its own concurrency revision and never rewrites model-turn
receipts. A browser acceptance harness must exercise the actual HTTP service,
native execution, SQLite state, and responsive UI. Its small native model is an
execution fixture, not evidence of useful trained-assistant language quality.

### Dragon

A signed-in user can create a rights-scoped research mission, inspect captured
source passages, review the evidence and decision brief, and reopen the saved
mission. Sharing rechecks owner/session/source revision. Evidence transferred
to Jeeves remains reviewed untrusted text with source provenance. Source review
and local import do not grant publication rights or certify factual truth.

### Skeleton

The surrounding application provides reproducible startup, accurate readiness,
one canonical owner per capability, and coherent navigation. Installation,
backup, recovery, and rollback must preserve user state. Device and release
requirements retain their separate qualification status.

## Definition of completion

- The essential journey reaches a durable result and later continuation.
- Every primary control has a working, intentional outcome.
- Loading, empty, validation, failure, retry, and success states are usable.
- Access, model identity, source scope, and state ownership remain enforced.
- Desktop, mobile, keyboard, and visible-focus acceptance are exercised.
- A fresh checkout can reproduce setup and the recorded checks.
- Relevant PRs have an explicit integration disposition.
- Draft descriptions report the current implementation and observed evidence.
- Competitive and production claims match independently obtained evidence.
