## Explicit two-way studio draft bridge (source-level addition)

## Offline tenant/session storage isolation

Cross-editor handoffs and full Galaxy drafts now use owner-scoped local AsyncStorage keys. The scope fingerprint comes from a local SHA-256 digest of the active bearer token after SecureStore/localStorage token initialization. **Raw bearer tokens are never used as draft keys, and draft persistence never performs a network lookup.** An anonymous session receives a separate anonymous namespace. Account epoch checks fence storage publication and consumption; stale data is unmounted when users log in or out. A scoped write that detects a concurrent account switch deletes its partial publication and fails closed.

This source-level isolation is exercised by `frontend/scripts/skeleton-forge/storage-scope.test.cjs`, which injects deterministic offline token, digest and storage mocks to verify Alice/Bob isolation, one-time consumption and auth changes during writes. Real device, reinstall, token renewal and hardware-specific recovery remain to be qualified. An intentionally conservative limitation is that rotating a bearer token also rotates its local key: this release does not migrate unscoped or differently scoped drafts without independently verified account continuity.

## Portable, source-verified Godot project export

GameForge's existing `/api/skeleton/run` route always removed the complete generated file bodies for its normal frontend calls, and the UI exposed no way to obtain the game. The export now has a separate explicit questionnaire choice: **Prepare Godot ZIP**. The choice is carried through Forge ↔ Galaxy handoffs; all non-opted-in builds retain their original lightweight response shape.

When explicitly selected, the same synchronous forge run asks for `include_files: true`. The server refuses to return file bodies unless the build succeeded, the source manifest is present, the target is Godot, the file count is at most **256**, and total UTF-8 source is at most **8 MiB**. If any source export condition fails, the game run result stays available while the source bodies are excluded and the export status is `unavailable`. These limits prevent accidental transfer of an unbounded generated project to a phone.

On success, GameForge's Run panel shows **Save or share Godot ZIP**. It packages the **exact file bodies returned by that successful run**, without performing a second generation or remote upload. `sourceArchive.ts` implements a deterministic, ordinary ZIP archive with stored entries, CRC-32, central-directory records, strict paths, a 256-file budget, an 8 MiB source budget and a 9 MiB package budget. It requires `project.godot`, a matching inventory, and an original source-manifest digest. `shareSourceArchive.ts` independently checks every file's SHA-256 **and** the canonical manifest SHA-256 using `expo-crypto` before writing or sharing. User/account changes during the asynchronous operation abort publication.

On Android/iOS the generated ZIP is written to app cache through Expo SDK 55's `File` / `Paths` API and passed to the system-native `expo-sharing` sheet for a user-chosen save or transfer. On web it uses a user-initiated Blob download. The application does not upload these project files to a cloud provider. The archive is a **Godot source project**, not a compiled, signed, independent executable, and requires a compatible Godot editor/runtime for desktop build/export.

New hermetic coverage: `skeleton/testing/test_gameforge_source_archive.py` exercises the bounded API, no-export defaults, denied JSON/failed/unsealed exports and oversize source rejection. `frontend/scripts/skeleton-forge/source-archive.test.cjs` parses local and central ZIP records, verifies byte-for-byte project roundtrips and deterministic ordering, and checks traversal, bogus manifest, mismatched inventory, 256-file and 8 MiB limits. Both suites are in the exact-head qualification workflow. Actual mobile share-sheet and Windows Godot import remain independent device/first-install release holds.

## Exact-run Godot source ZIP and account-scoped delivery (November 13 continuation)

The existing forge endpoint previously removed all generated source bodies from its normal result and left users without a portable way to open their game. This PR now offers a **deliberate, opt-in source ZIP**:

1. The questionnaire's **Prepare Godot ZIP** choice sets `include_files=true` only for Godot output. Without that choice, the preexisting response remains source-light and no ZIP is prepared. The choice survives explicit GameForge ↔ Galaxy navigation and is omitted from JSON blueprint export.
2. The backend returns the **exact files generated by that same successful run**, not a second, potentially divergent build. The route enforces at most 256 files and 8 MiB total UTF-8 source, admitted ASCII portable paths, source projector path validation, and **recomputed** per-file SHA-256 plus overall deterministic source-manifest equality. Any mismatch, malformed Unicode, reserved Windows device path, unsafe name or over-budget file set results in `source_export.status='unavailable'` and suppresses raw files without changing the underlying build result.
3. `sourceArchive.ts` creates a deterministic ZIP store archive with UTF-8 names, CRC-32 in local and central entries, fixed DOS timestamps, sorted paths, and explicit entry/central-directory byte lengths. It refuses path traversal, hidden path components, case aliases, reserved Windows device filenames, malformed UTF-16, ambiguous project roots, unlisted files and any 9 MiB archive budget excess. An exact-size typed UTF-8 encoder prevents large boxed-number allocation pressure on mobile devices.
4. The user-initiated **Save or share Godot ZIP** action recomputes every returned text file's SHA-256 in Expo Crypto and independently verifies the overall manifest before exporting. Web creates a browser ZIP download; Android/iOS share through the local OS sharing UI. The temporary native ZIP is deleted after sharing or cancellation/failure, and the web object URL is revoked after download initiation. No cloud artifact upload or external model is invoked.
5. An authentication-epoch and request-generation fence clears completed and pending GameForge run results on logout/account change, aborts superseded requests, blocks late response publication, and prevents sharing files created under a different account. The archive and share step also recheck that fence.

Focused qualification is in `skeleton/testing/test_gameforge_source_archive.py` and `frontend/scripts/skeleton-forge/source-archive.test.cjs` plus `run-session-isolation.test.cjs`, included by the dedicated exact-head workflow. Tests cover portable ZIP structure, byte-preserving Unicode, deterministic file order, malicious file names, source/manifest tampering, size/file caps, explicit opt-in, handoff continuity, session rotation and temporary data cleanup. These are source and regression contracts; a real installed app/browser export roundtrip and Godot 4 project import must still pass independently.

**Important output distinction:** A source ZIP is intended to be opened and built with a compatible local Godot engine. It is not a signed executable, an APK, a Windows installer, a first-install guarantee or proof of release provenance. No such claim is made until independent device/engine and security qualification completes.

## First-install Studio reconciliation and HTTP custody boundary

The first-install Studio shell had a separate persistence code path from the advanced Forge cockpit. It previously initialized a partial `QuestionnaireState` and its project sanitizer reconstructed only `step/vision/brief/beats/options`, silently discarding the recovered ten-axis controls, Galaxy specialization, native quest, playable archetype opt-in, headless qualification mode and ZIP-export selection every time a saved project reloaded. The first-install build screen also did not expose the newly implemented source-share button.

The unified first-install project model now creates a complete independent questionnaire from `INITIAL_STATE` and safely restores each modern field (whitelisted finite axes, recognized historic genre, bounded quest length, explicit playable/playtest/export flags), while older questionnaire records get safe defaults without losing their authored brief or beats. A completed live run may still share the exact source ZIP, but persisted project history retains **receipts and metadata only**: raw generated source files and the source-manifest file inventory are not written into the general AsyncStorage project snapshot. A restored history entry explicitly marks a formerly ready ZIP as unavailable and explains it must be saved from the original live run. First-install's own `BuildStatusScreen` now delegates the same account-fenced share action as the advanced cockpit.

The existing first-install AsyncStorage keys were global to the device, meaning a new account could inherit another sign-in's project list. These are now scoped by the active locally held bearer SHA-256 fingerprint, using the same offline auth-epoch fencing as the advanced creator drafts; changing the authenticated session remounts **all** first-install Studio state, including compose, run, projects and cockpit console. Raw bearer values are never stored as key components. A new sign-in does not automatically claim old unscoped projects. The user may explicitly choose **Import my legacy local projects**, after a warning that such projects might belong to a different prior account. Import reads legacy storage without changing it, validates the project set, drops raw run-source payloads, refuses any corrupted batch, and never overwrites an existing account project with a colliding ID. Existing unscoped records remain as a read-only migration source and are not silently deleted.

**Known limitation:** account scoping uses the locally held bearer fingerprint, not a durable network-verified principal ID. Rotating or replacing a bearer token can make the old token's scoped storage temporarily inaccessible even when the human account is unchanged; no unsafe cross-account automatic migration is attempted. A later verified stable-principal migration is needed for seamless token rotation. The legacy import path is an explicit recovery route for the old unscoped data only, not a token-rotation bypass.

The HTTP `POST /api/skeleton/run` route now **rejects caller-selected `project_root` and `overwrite` before pipeline execution**. It always sets `project_root=None`, `overwrite=False` internally. Native local/CLI project publication remains separate; remote callers receive the bounded, manifest-verified source ZIP rather than using the API to write arbitrary directories on the backend host. The request model additionally bounds vision length, answer count and identifiers, operator-axis count, blend size, finite interpolation and other routing identifiers.

## Full first-install Studio ↔ advanced Forge return

The existing **Forge cockpit** entry on first-install Studio's brief/build screens previously navigated to an independent blank cockpit. It now sends the selected Studio project's complete bounded questionnaire to the advanced Forge editor **before navigation**. The one-time offline handoff is account-scoped and names both the **specific project ID** and its **exact source `updatedAt` revision**, not an arbitrary filesystem path, account identifier or server write.

An explicit **Save edits back to Studio** action appears in advanced Forge only when the route was entered from an identifiable Studio project. ## Studio return durability, revision fences and exact build-input custody

The first-install Studio-to-advanced-Forge return now uses a serialized **persist-before-acknowledge** protocol. `withCreatorBridge('studio', async ...)` keeps the original, locally account-scoped handoff until the Studio project has been validated and fully saved. Failed saving or an authentication-epoch change leaves the handoff in the **original** owner's scope; no operation reissues the previous account's authored data under the currently active account. A same-runtime lock prevents two consumers from acknowledging one envelope concurrently. An explicit bad/expired envelope remains rejectable, while the opposite target direction is preserved for its rightful receiver. The protocol does not claim multi-process or cross-device transactions.

Source-bound Studio revision values are now monotonically increasing ISO timestamps even if multiple edits occur during one clock millisecond, the system clock moves backward, or a build completion timestamp predates the latest edit. This prevents a stale advanced editor from passing an optimistic revision match when its originating Studio project was edited concurrently. A completed native build is compared with its **submitted** `RunRequest`; if the questionnaire changed while inference or Godot generation was in flight, the receipt remains retained but its current project is marked `Needs rebuild`.

Return acknowledgement can itself fail after the receiving project save has committed. The retry path therefore recognizes an **identical already-applied questionnaire** at the original project, safely acknowledges it without creating a second project, and still raises a conflict for different concurrently authored content. Tests in `storage-scope.test.cjs` and `foundation.model.test.cjs` cover successful one-time commit, storage failure retry, mid-save account rotation, same-millisecond edits, in-flight build changes and return replay with duplicate suppression.

**Qualification boundary:** these are committed source changes plus regression coverage; exact-head GitHub checks and real installed-device persistence/recovery remain required before any merge or launch claim.
