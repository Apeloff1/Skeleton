This original-game production manual documents one complete **domain × director × finishing-pass** family, part of the tenfold expansion from 500,000 to five million Forge Studio operations. Each contract invokes the existing source-changing game recipe, applies a gameplay overlay, adds director-specific topology, then writes finishing-pass map edits and an independently evaluated RPG event page. Where new actors or quests were authored, only those new records receive further pose/branch refinements. This is not an independent game engine or finished title.

## Gameplay intent and execution

- **Domain:** expedition; production work centers on interactive cast placement, quest-giver identities, and adventure travel.
- **Director:** audio_cues; directs the second source-editing stage toward gameplay, presentation and continuity.
- **Finish:** alternate_endings; changes selected source map cells, adds a separate RPG sensor-response proposal and adjusts only newly generated cast/quest components.
- **Data authority:** original typed `StudioProject`, existing authenticated tenant/project workspace, per-edit SHA receipt and host compare-and-set.
- **Actual native target:** existing Godot 4 expedition source emitter. Map/actor/quest edits are authored source; collision, executed audio, combat and economics still require native runtime verification.

## Implementation chain

1. Resolve authorized saved source and current revision; read the actual palette, actor catalog and native quest identities.
2. Search the exact operation using `generation=final&domain=expedition&director=audio_cues&finish=alternate_endings` with a page of no more than 64 metadata results.
3. Validate integer seed, bounded region and unique `instance_id`; reject any embedded dynamic subcommand.
4. Execute the original recipe, its world-gameplay system and the director, preserving all original project records.
5. Perform the finishing algorithm: paint real source tiles and append two-observation RPG page with a registered action.
6. Reposition only new actors and attach optional reachable quest stages only to newly authored quests.
7. Compute source hashes, run typed source revalidation and persist in one host-authorized compare-and-set transaction.
8. Export Godot terrain, expedition graph, NPC interactions and native quest source; inspect real game behavior before release.
