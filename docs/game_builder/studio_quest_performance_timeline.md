# Original quest performance timeline: source-replayed voice/window handoff

Studio A now connects two distinct source-complete verticals: **human-reviewed localized voice direction** and **causal authored chronology**. The performance compiler proves that every canonical played event has original reviewed dialogue cues, the source/session/locale/ending leases agree, and the estimated voice performance plus a human-reviewed buffer fits the authored time window. It does not synthesize speech, verify a real voice identity, measure observed playtime or qualify native game playback.

Flow: user prompt → typed source-bound proposal → edit the per-event `buffer_ms` and `reviewed` fields in a private JSON plan → compile using canonical source and replayed voice/chronology receipts → deterministic playable review HTML → private non-overwriting receipt → exact restore/replay. Cue identity, action order, source digest and chronological windows are immutable in this integration plan.

CLI: `python -m scripts.studio_quest_performance_timeline_cli` with the same `--project`, eight private component receipt files and `--accept-topic` options as localized character handoff. Supply `--voice-file` and `--chronology-file` for the two reviewed source receipts. First invocation produces a typed proposal; edit and review all rows and pass `--plan-file` for compile. `--preview-html` emits a CSP-locked, read-only proof. `--publish DIRECTORY` creates `studio_quest_performance_timeline.json` exclusively and `--restore DIRECTORY` replays exact source, components and receipt.

Jeeves read-only capabilities `studio_quest_performance_proposal` and `studio_quest_performance_compile` enforce exact expected component digests, operator authorization, immutable registered inputs and strict typed payloads. Estimated dialogue budget is explicit: each displayed Unicode codepoint contributes 70 ms (minimum 300 ms per line), plus authored pause and reviewed per-event buffer. This is a conservative authoring heuristic, not real speech duration evidence.

Limits: at most 64 played events, 128 cues, 128 KiB plan, 384 KiB receipt, 256 KiB HTML, reviewed buffer 0–30,000 ms. Fail-closed negative tests cover stale components, forged digests, mismatched canonical session, event identity, unreviewed or oversubscribed windows, private symlink/forged receipt, CLI and Jeeves authority. `canonical_quest_replay_verified` and `authored_window_fit_verified` are sandbox proofs; `estimated_not_observed` remains true, `audio_generated`, `native_gameplay_verified` and `release_certified` remain false. Source-backed tests and exact-head CI must pass before promotion or release.

The offline HTML editor is available with `--editor-html`. It uses a hashed inline script under a deny-all CSP, accepts only source-leased event identities, edits bounded per-event buffers and review flags, and exports a JSON plan for mandatory canonical CLI revalidation. No browser edit writes to the repository or constitutes a compiled receipt.
