# Adversarial original-game world What-If Laboratory
**Authored:** 2026-10-12, Europe/Oslo. **Parent:** replay-only interleaved source save PR #3701 and event-level game clock PR #3699.

## Real game-engine purpose
Creators can submit one **already replay-verified original interleaved game world**, comprising actual physical collisions, source-verified farming harvests/sailing cargo/aircraft landings and canonical NPC-world actions, to a bounded what-if laboratory. Instead of brainstorming theoretical outcomes, the laboratory constructs alternative orders of precisely those same sources and **independently executes the complete actual original game sources and NPC world for each alternative**.

## Adversarial methodology
The baseline must independently verify against the original source/editor scene/settings and complete interleaved event timeline. The laboratory explores adjacent action swaps breadth-first, starting with shallow, explainable causal edits before deeper combinations. By default it tests at most 24 candidate orders, accepts at most 8 fully replayed alternatives, and explores two swaps deep; ceilings are 48 attempted orders, 16 accepted alternatives, three layers deep. Multiple events from one original source session cannot be directly inverted; the engine also independently rejects any alternative that skips, repeats, retrodates or disguises a genuine source event. A rejected candidate is recorded as rejected, not upgraded into a plausible success story.

The lab derives each original event's actual world-tick duration from the baseline's independently recorded source clock; it reconstructs candidate clock positions rather than incorrectly assuming every original NPC action consumes one tick. Multi-tick waits and all canonical original world actions still execute through the real NPC gameplay state. Any candidate that changes the legal timing or violates a quest/scene/physics constraint fails closed. Every admitted alternative receives a unique source-position identity, exact authored candidate timeline, original full-campaign digest, per-step original event IDs and actual NPC eyewitnesses, causal quest IDs, source receipt identities and final world digest.

## Game-design lenses (not model promotion)
The original creator chooses a factual priority: **eyewitness coverage**, **community recovery**, **resource stewardship** or **earned quest progress**. These are explicit lexicographic metrics over original game-state numbers, not fabricated expert-review scores or evidence of statistical/model improvement. The source-derived score components include genuine direct eyewitness memories, separate rumors, earned quest completions versus exploit paths, remaining site integrity, original finite site stock, NPC-world supplies/stamina, reputation and gold. Every candidate includes the complete measured metric vector and delta from the baseline. A scenario is labeled as 'better on the selected metric' **only if the lexicographic score strictly improves**. If no candidate improves the selected metric, no improvement is claimed, even when a different valid timeline is displayed.

The best observed candidate is only the best among the bounded successfully replayed alternatives under one author-selected objective, not a globally optimal event ordering. The candidate search is deterministic and limited, not an evolutionary optimizer searching every possible schedule. SHA-256 source chains enforce repeatable transcript identities; they are not private-key identity signatures or native-device certificates.

## Studio
An operator-facing panel displays the four factual priorities and three bounded swap depths. **Adversarially replay bounded original game alternatives** invokes the authenticated local server; server independently constructs and verifies the complete original source experiment twice before returning it. The Studio displays the original source metrics, accepted/rejected scenarios, evidence receipts, actual outcome deltas and any strictly measured improvement. A specific accepted candidate may be copied to the original event-clock JSON editor, but **nothing is executed, saved, published or AI-trained automatically**. The creator must separately click the preexisting independent game-world replay control to test/apply that edited clock.

## Verification
Eleven adversarial engine tests cover real causal reordering; exact whole-world replay of each candidate; factual NPC source-event counts; all four priorities; no false better-than-baseline claims; deterministic search limits; malformed objectives and complexity budgets; unsourced, omitted or forged source-game inputs; metric/ranking/witness and source-ID tampering; actual NPC source-memory custody; and true multi-tick original-game command duration. Three Studio tests validate authenticated controls, meaningful operator confirmation and the no-automatic-commit/release boundary. Tests join the full exact-head Windows and Ubuntu reference game engine suites and existing native Godot integration checks.

## Explicit boundary
**Event-level replay of the original reference engines only.** This milestone does not claim synchronized 60 FPS across all engines, exhaustive optimality, player-hardware certification, a commercial native cross-engine campaign, a statistical experiment over independent random seeds, source-file mutation, background automation or promotion to persistent AI model weights. Future multi-seed confidence intervals, perturbation-source coverage and native causal replay need separate evidence lanes.
