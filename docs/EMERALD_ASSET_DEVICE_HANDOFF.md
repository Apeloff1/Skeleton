# Operator handoff: actual original asset and physical qualification

The optional full-model viewport admits only one model read/hash/decode/residency per JavaScript realm. A memory hint below 4 GiB blocks original-model loading; absence of that browser hint is not a physical memory guarantee. A canceled decode holds its lease until disposal/settlement. Existing prepared motion remains available.

The original three separately distributed files are not in Git, and no fake replacement is permitted. On the asset custodian's machine, use the retained original directory:
```sh
python scripts/emerald_asset_preflight.py --directory /trusted/emerald-downloads
```
Use explicit --web, --source, --model if the files reside in different locations. The command emits exact byte verification status for each and returns nonzero for any missing or rejected input. Only after all three pass, run the existing offline web installer, offline source/model stager, and catalogue/admission generator in their documented order. Build the web application with the installed web pack; open both authenticated crawler surfaces and inspect the real clips. Keep source ZIP, pin and assets intact.

Then on actual supported Windows/Unreal/RTX hardware run the staged project's existing qualification tool, inspect its receipt via scripts/inspect_emerald_native_receipt.py, review physical GPU captures and actual presented-frame measurements independently, and complete separate folded-wing/texture/anatomy artist signoff. A successful preflight is never engine compilation, hardware evidence or release authorization.
