# Original Game Builder: Adversarial Multi-Context World Robustness
**Authored:** 2026-10-12, Europe/Oslo. **Depends on:** #3708 original world What-If Mirror, #3701 interleaved portable source saves, #3699 interleaved game clock.

## Why the additional evidence layer matters
A bounded alternative event ordering can improve the number of people who witnessed a physical incident in one authored 7×7 NPC world, but reduce visibility in a different climate, day phase or NPC start configuration. The prior What-If Lab deliberately reported only measured success *inside one world*, never statistical generalization. This milestone runs the exact same source-verified event ordering through **two or three separately signed original NPC world scenes**, preserving the actual other game sources and original event identities while changing only signed world context.

## Engine implementation
`advanced_world_robustness.py` requires a complete original source-verified What-If proof, physical episode inputs, independently verified farming/sailing/flight sessions, the original world settings and two to three **distinct** signed NPC world scenes. The first scene must be exactly the baseline world from the original What-If experiment; no author can replace it with a more favorable alternate. It independently re-verifies the entire prior What-If proof and every original input source, and independently replays the actual baseline and at most four selected alternative timelines in each world.

Every alternative must execute completely without missed/duplicated source events, impossible NPC movement, nonexistent firsthand testimony, resource inflation or invalid world clock changes in **every** supplied context. Alternatives that cannot validly play in one scene are explicitly rejected and are not given a partial or optimistic performance score. Source-local physical collision contacts and genre achievements remain genuine inputs; there is no text-based extrapolation of gameplay.

## Measured evidence
Every independently completed run produces an original campaign digest, source event-chain head, final world-state digest, actual event-origin order, first-hand witnesses, and NPC direct versus rumor memory records. The engine measures genuine quest completion/exploitation, site integrity, finite stock/supplies, stamina, world time and original NPC movement. For each candidate/context pair it records metric deltas against that context's own **independently replayed baseline**, plus whether the chosen lexicographic priority improved strictly, stayed equal or declined.

Results distinguish four different and non-equivalent statements: (1) *best observed worst-case score* among bounded actual tested candidates, (2) *better than the worst tested baseline* on that selected world-design objective, (3) *not worse in any tested context*, and (4) *strictly improved every tested context*. The comparison never labels a one-scene win 'robust', and never implies population confidence, generalization beyond these scenes, continuous model learning or proof of SOTA. Candidate selection is bounded and deterministic. Hash digests are repeatable source identities, not signed author authentication.

## Studio
A new operator panel generates independently signed quest-director world scenes with different seeds, day phases/climates, source-scene digests and original layouts. Authors choose two or three scenes and run **Replay candidates across authentic NPC world contexts**. The authenticated local server independently validates the complete original source, every game result and each claimed comparison. The UI displays actual baseline metrics, real alternative outcomes by context, genuine rejections and separate weak/strong improvement claims.

`Copy best observed cross-context candidate to editor` is deliberately restricted: it only copies a candidate if it was independently replayed in every context **and was not worse in any tested context**. Even then, the control only changes the editable interleaved timeline; creators must separately replay that world before using it. No original files, NPC reward counters, saving slots, public releases or model weights are changed automatically.

## Determinism and cost
Finite controls: 2–3 independently signed worlds, up to 4 admitted candidate scenarios, and the bounded, already verified 48-attempt/16-admission source what-if input. Computational cost scales with worlds times reviewed candidates because **full replay is mandatory**, not shortcut simulated NPC memories. The local Studio defaults to two additional-context checks for up to two fully replayed alternatives, to bound consumer-grade device work. Broader game-world performance requires separately authored statistical/multi-seed experiments and confidence procedures.

## Adversarial tests
Eight real engine tests validate distinct source scenes, actual NPC memories and game-derived source digests, protection against single-world false improvements, strict across-context comparison semantics, deterministic worst-case selection, invalid/duplicated/swapped world scenes, typed candidate budgets, forged eyewitnesses/metrics/release claims and tampered original genre achievements. Three Studio tests ensure authentic signed-scene creation, reviewed candidate adoption and independently verified server endpoints. Full exact-head Windows and Ubuntu game-engine CI is mandatory, with native Godot gates retained as integration controls.

## Boundaries
These measurements describe only deterministic reference-engine event-level gameplay. This work is not a native multi-engine Godot simulator, a global optimality proof, a randomized controlled experiment, a generalized AI model update, a cloud background worker, or a console hardware certificate. Exact-head CI must pass and parent PRs must be reconciled before integration into main.
