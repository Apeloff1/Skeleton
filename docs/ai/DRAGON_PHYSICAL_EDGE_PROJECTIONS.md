# Physical evidence-edge projections

Optional ten-file graph evidence storage per owner, in addition to the ten-file text indexes. Canonical lead/edge creation, source grant, outbox settlement, graph quotas and snapshot revocation remain transactional in the original owner corpus ledger. Physical edge files are independently writable projections, **not** canonical authority or a replacement for the primary writable graph.

Set SKL_DRAGON_LEAD_EDGE_ROOT to a pre-created operator-private directory. Enroll via `python -m core.dragon_lead_edge_shards --scope-json /private/scope.json --acknowledge-metadata-index`. Existing lead scheduler advances one edge lane per maintenance pulse; initial keyset scans and coalesced dirty-edge batches are bounded at 512 records. Canonical triggers publish dirty edge identities and revision/lineage stamps within the same transaction as the source mutation. No independent source fetch or authority. Physical files are range-partitioned by exact edge ID. Forward and reverse edge pages merge deterministic per-lane results only if every lane agrees with the same canonical source read snapshot. Returned evidence rows and snapshot revocation/expiry fields are read from canonical records. Missing, stale or mismatched projections fall back to existing canonical queries. Restore divergence can require re-enrollment with --reset-derived-edges; old epoch directories are disposable only after coherent backup and writer stop. Existing owner migration invalidates enrollment rather than copying stale projection state.

This write/scan projection does not eliminate canonical graph writer serialization. The next architectural boundary is a genuinely authoritative distributed graph with cross-shard parent/evidence identity, snapshot and quota commits, recovery and consistent outbox settlement. Do not promote derived evidence to authority prematurely. No live device probes or capacity measurements have been performed. Review-only.

Run backend/tests/test_dragon_lead_edge_shards.py and backend/tests/test_dragon_manifest_write_lanes.py with the inherited graph, migration, media/cold and security suites on exact head. Physical hardware capacity, sustained concurrent write speed, crash and independent backup recovery require real deployment-device tests.
