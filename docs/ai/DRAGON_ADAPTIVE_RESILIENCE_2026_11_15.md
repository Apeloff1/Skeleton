# Dragon adaptive resilience and source-authority boundary
Date: 2026-11-15. Status: implementation candidate, review only.

## Authority and threat model
The existing CrawlRun and owner-scoped CORE_DB application remain the sole dispatch and checkpoint owners. The crawler treats source text, titles, markup, agent configuration files, extracted documents, unknown embedded directives, and robots comments as external data. Site-provided access and retention restrictions are honored; arbitrary source instructions are not an authorization. A source never changes tool permission, request scope, identity, credentials, consent, code or grant.

A bounded deterministic inspection precedes discovery, retention, and retrieval. Known instruction artifacts are quarantined regardless of pattern score. Unicode compatibility normalization, formatting-code removal, HTML entity decoding, and a second split-markup view detect common indirect-instruction forms. Pattern categories are heuristic signals, not proof of malice: legitimate security documentation may be held. A no-hit result is not permission to execute anything. Current code does not claim to detect every encoding, language, binary, or semantic attack.

The same canonical snapshot commits incidents and the charged response outcome. The incident ledger is separate from the rolling 64-event diagnostic tail, bounded by the finite request budget. It records stage, sequence, URL digest, category counts and permitted input/match fingerprints, not raw instructions. Site retention restrictions suppress source fingerprints; no raw attack payload is copied into a new store. Inspecting robots comments does not override valid rules. The authenticated UI exposes bounded metadata and host observations; ordinary search, export and source context reject held sources, not merely label them.

## Fault recovery and adaptive operation
The already-admitted frontier remains the only candidate set. Balanced and coverage strategies blend operator-query/URL utility with bounded Beta-prior outcome estimates. FIFO selection remains compatible. Local outcome events provide evidence; source prose does not set priority or change credentials. Repeated transient failures extend host-wide cooldown. Access denials (401/403/451) hold further automatic acquisition from the affected host until the current consent horizon. Existing server Retry-After, robots delays, scope, reservations, lease fencing, physical custody and cancellation retain precedence. Cross-origin recovery never invents alternate identities or access paths. Redirects and restored destinations are subjected to structural and credential-bearing URL vetoes.

Robots processing has a 512 KiB per-policy capacity under the default application response limit, a finite shared cache and an explicit reserve for deny policies. Smaller operator byte budgets, malformed data and exhausted capacity fail closed; no rule truncation grants access. RFC 9309 requires at least 500 KiB parsing capacity, and its rules do not constitute access authorization. Existing Python robots matching behavior and all RFC parsing edge cases still require independent conformance review. This is not a legal certification.

## Protocol and performance continuation
Merged exact product-specific REP groups, bounded wildcard and terminal matching, percent-octet normalization and strictest nonstandard pacing are implemented in the canonical cache. Invalid pacing or work-budget exhaustion denies acquisition. The prior stdlib matcher missed several of these cases. First-page pacing and redirect Retry-After are now checked before subsequent dispatch. Runtime parser cache is keyed to exact checkpoint policy text and timestamp; no new durable ownership. The coverage scheduler builds its retained-source index once per selection rather than repeating a complete source scan for each candidate. Multilingual and escaped source-instruction detection is heuristic; unknown REP fields and comments are isolated. Run `python -m scripts.benchmark_dragon_crawler --repetitions 3` for a network-free, SHA-bound corpus baseline: three strategies across budgeted relevance, bounded discovery with hostile source and denied links, and transport interruption/restart. It reports deterministic trace and source set digests, recall, precision, request and byte cost, incident disposition, checkpoint size and restoration timing. External competitors remain unexecuted; protocol conformance still requires independent corpus testing.

## Deeper runtime containment and exact-current recovery

The canonical acquisition path now launches complex parsers and structured discovery in disposable POSIX children with a three-child process-local limit, a 512 MiB address-space cap, five CPU seconds, finite stdin/stdout, and a deadline no longer than the remaining slice or eight seconds. The parent derives source hashes and authority from the charged response, never from child-supplied provenance. Child faults settle actual bytes, reject that item and allow later admitted work to continue. Python audit restrictions and a minimal environment are defense in depth, not a complete security sandbox. Small HTML/plain text retains its existing bounded in-process path; PDFs retain their own resource-limited worker. Complex formats on non-POSIX platforms are held pending equally strong native limits.

Exact duplicate captures now retain bounded replay-validated URL/body-digest receipts while contributing only one normalized document. Ordinary source retrieval and Jeeves context select exact source spans by deterministic relevance-weighted novelty and origin diversity; similar but distinct claims remain candidates. Context projection retains references and small candidate passages rather than full per-session snapshots and revalidates custody before returning. Similarity does not establish factual accuracy or independence.

The Mongo checkpoint publication now admits one atomic primary, identity witness and compressed exact-current copy (when it fits the existing finite write envelope). Quiescent, current-consent sessions can repair accidental primary field corruption by decoding the exact witnessed revision, validating runtime, request, owner scope, consent and source policies, and committing against version/worker/status fences. No ancestor rollback, physical-exit claim, worker start or grant mutation. Missing/stale/corrupt copies, active workers and expired consent hold. Entire-row/database loss is outside this redundancy guarantee; both fields share one storage authority. Erasure removes the copy and witness. Dashboard metadata explicitly distinguishes replica presence from verification. New CI fixtures cover actual disposable children, charged parser failures, duplicate custody and tamper rejection, diversity, bounded replica decoding and repair races. Results remain unverified until exact-head checks complete.
