# Recovered resource-aware assurance execution

Connect the canonical CPU, memory, power and anti-thrash owners to the
existing six-source-suite assurance runner. resource-assurance runs only
explicitly selected source suites, sequentially, after a bounded series of
fresh host measurements. No suite starts when the gate holds. Missing
memory, stale observation, critical pressure and probe failure stop admission.
Each completed suite retains its actual returned case evidence and a second
pressure observation. Historical receipts are not credited as fresh tests.
The CPU/energy planners remain directly accessible from installed routes.
This is cooperative admission: it does not reserve memory, preempt a
running suite, or enforce a process RSS limit.

gguf-source-preflight connects the canonical descriptor-bound GGUF SHA
and header check. It requires operator authorization and an independent
SHA pin. The existing owner rejects unsupported platforms/unsafe custody.
This is not tensor validation, approved tokenizer, rights, load, native
inference or device evidence. No model bytes are modified or downloaded.

Source tests cover the actual gate logic, fixed trust fixtures, refusal
before file access, and the original source preflight tests. CI execution
and hardware observations are not claimed by this commit.
