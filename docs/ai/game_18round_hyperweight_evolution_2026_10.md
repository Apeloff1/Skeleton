# Original-game AI 18-round Dragon / Jeeves / Adversarial shadow-weight evolution

**Version:** October 2026 game-AI follow-on to the competitive 102-facet / 4,080-probe, 27-page council and real local-reviewer SGD lanes.

**Scope:** Exactly **rounds 3–18** (16 new consecutive work stages). Rounds 1–2 remain the existing deliberate research and model-aftercare reasoning layers. A round is never proof of model quality merely because it was queued, assigned or signed. A real measured improvement requires a separately replayed original-game training corpus, a frozen validation and heldout TEST split, improvement against the active champion, independent original-game usage and idle observations, industry-quality source code review, the actual sandbox quality decision and the existing six-reviewer game-model registry approval. No commercial-game victory is claimed from metadata-only comparisons.

## Core design: expected task utility is not artificial training

The term **hyperweight** refers here to a *bounded, modular, task-loadable knowledge/policy reference* in the existing game reviewer and almanac ecosystem. It does not mean an uncontrolled new foundation-model tensor, secretly retrained Dragon/Jeeves weights or an externally certified commercial AI adapter. Knowledge references, original-game fit results, independently signed sandbox qualification, stage/activate authority and actual learned parameter bytes remain separate.

Each potential original-game knowledge module has:

- Specific original user game, task, era, genre, themes, requested original capabilities and conservative memory allowance.
- Source-version-bound Dragon almanac identity, the exact original task digest and actual comparison against authenticated relevant predecessors; comparable genre history is **not** falsely described as causal ancestry.
- Distinct, signed and independently grouped historical original-world **usefulness outcomes**. Duplicate group reports cannot inflate the inferred result.
- A **Beta-binomial prior (2,2)**. With observed independent successful improvements *s* and failures *f*, posterior mean is \((s+2)/(s+f+4)\), a heuristic expectation, **not** a calibrated probability that a commercial game will win. A one-sided conservative proxy uses mean minus 1.645 standard deviations, floored at zero. Unknown outcomes deliberately lower confidence.
- Explicit relevance components for current genre (27%), era (18%), themes (20%), original-game capability overlap (35%). Separately audited predecessor coverage contributes up to 15% of final applicability; unknown ancestry contributes zero, not an imagined heritage bonus.
- Priority ordered by conservative historical utility × task applicability and predecessor evidence. Source rights and game-code evidence separately determine if the module is research-only or may be *considered* for a shadow experiment. A reference-only article never becomes model training data.

**Crucial limitations:** these coefficients are transparent engineering defaults, not independently calibrated outcome forecasts. In production they require backtesting for project-mix fairness, actual professional-game task usefulness, miscalibration and era-transfer regressions. If all source records belong to one reprinted article or one original game, the model must not claim four independent successes.

## Isolation of shadow weights and the verification sandbox

\`game_18round_shadow_sandbox.verify_shadow_in_sandbox\` only accepts a source-plan-exact queued ticket, real installed champion policy (needed to *prove* net improvement), a professional original-game code review receipt, explicit operator/host consent and fresh usage and idle replay cohorts whose project IDs do not overlap TRAIN/VAL/TEST or each other.

It trains with the existing actual SGD ranker and validation-only parameter selection. It then recomputes the frozen heldout evaluation, numeric champion uplift, critical recall, calibration and per-game/attack-family regression checks, and replays the **fresh** usage and idle observations via \`evaluate_fresh_cohort\`. Newer mathematical weights are **not** automatically better. No active champion, no incremental gain, a single critical regression or absent independent cohort means the candidate stays a research/shadow backlog item.

The resulting immutable \`SandboxVerification\` must be **signed by a second configured verifier distinct from the round reviewer**, bound to the exact evidence digest. An optimizer output, a handwritten boolean, a forged signature or a queue position cannot masquerade as completed sandbox proof. It can only authorize potential *staging* through the existing \`ReviewerRegistry\` workflow; that registry still owns six independent reviews, separate live usage and idle checks, rollback and explicit operator activation.

\`order_verified_hyperweights\` builds a cold-load priority plan from proof-bearing candidates and a bounded ≤25% consumer-host RAM allowance; this function never writes a tensor file or installs a remote foundation adapter. Older era, genre, theme and hardware constraints may change which modules are candidates, but must not change sealed experiment results.

## Signed historical outcomes

\`game_18round_relevance.py\` records every usefulness vote with:

- The exact original-world project digest and evidence receipt digest.
- An independent evaluation group name and outcome.
- A configured reviewer credential HMAC over all fields.
- One vote per topic and independent group. No duplicate group, repeated blog post or publisher syndication inflation.

A report with fewer than two independent observations remains research-only. Source almanac rights are checked before stage 3 by the existing Wiki/Dragon issuance process; the top-level production admission must recheck source references against the *live* \`RightsLedger\` and fresh reviewed \`KnowledgeBrief\` immediately before actual use. Stage 3 cannot grant model-training rights.

The prior is only a heuristic. Eventual promotion needs empirical calibration, statistical confidence over appropriately sampled player/projects, hardware-specific evaluation, and legal/ethical rights review. None of those can be proven from signatures alone.

## Durable crash recovery

\`game_18round_journal.GameEvolutionJournal\` journals accepted rounds under the real \`GameWorkspace.training\` folder as an isolated SQLite WAL archive. It uses one transaction per new stage, exact parent state SHA, unique chronological receipt digests, monotonic timestamps, review signature and source identity verification, compare-and-append stale-head veto, duplicate-JSON rejection and no silent stage skips. A forged “shadow_approved” flag without a sandbox-approved round fails during historical replay. Human reviewers keep their signing keys outside this database.

This is local crash integrity, not blockchain/notary immutability. It does not persist crawler HTML, private conversations, untrusted logs, heavyweight model weights or secrets.

## Source rights and operational security

Rounds 11–12 distinguish three different concepts:
1. **Destination found:** a reviewed HTTPS source reference, safe to offer to a separately controlled crawler after DNS/terms/robots/redirect checks.
2. **Evidence reviewed:** a separately signed response/revision/log digest for a source, *without exposing raw crawler payload* to the model candidate.
3. **Training authorized:** only the live canonical RightsLedger allows training when it has explicit model-training permissions. A source merely marked \`training_cleared\` by a logger is not sufficient. The sandbox only uses authentic, independently witnessed original-game training replays.

Crawl failures must be retained as failures, not relabeled as novel sources. Round 18's adjacency plan uses the existing Dragon planner and returns *query intents*. Fetching, indexing, rechecking and independent editorial/technical evidence remain separate execution stages.

## Quality acceptance and adversarial attack inventory

- Repeated/reprinted usefulness votes, forged signatures, unsupported ancestry/cross-genre cause, spoiled TEST, hidden model version, malicious crawler URLs, source digest/revision substitution, raw-log leakage, review role forgery, background activity while hot/busy.
- Selector gaming through threshold/drift, negative-only or positive-only datasets, same-game train/test leakage, single-category overfit, false champion uplift, underpowered usage/idle cohorts, missing high-severity recall, errors that block legitimate original play.
- Duplicate knowledge topic/module aliases, memory budget overcommit, cold-start unfairness, source-rights revocation and historic save rollback.
- Genre convention plagiarism: legal facts and gameplay abstract patterns may inspire new original approaches, but protected expression, art, level maps, names, music, plot and code are not copied.

**Current production limits:** This implementation includes the 16-round sequencing/control plane, probabilistic priority heuristic, trained local shadow sandbox, safe crawler mission and destination/log handoffs, modular load plans, journal and tests. It does **not** start an always-on network crawler, infer actual era-by-era commercial relevance without a verified game dataset, generate genuine foundation-model shadow tensors, or automatically activate Dragon/Jeeves parameters. Native game builders, model-serving adapters, user-visible research queues and external expert evaluation require further separately authorized integration.
