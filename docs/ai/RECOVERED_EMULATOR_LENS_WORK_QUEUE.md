# Recovered emulator lens work queue

The original source-reconstructed emulator lens campaign is now connected
to a bounded installed operator queue. Every registered review lens gets
three distinct work items for Jeeves playback, consent-scoped Dragon
observation and adversarial counterexample review. The index is bound to
the exact canonical catalogue and training-report digest; insufficient
source-run coverage remains a held work state.

Externally supplied metadata receipts are checked against exact task,
source receipt set, lane, consent scope, reviewer, artifact digest and a
pinned ordered submission chain. Each lane uses a different operator-held
HMAC key supplied through the environment. The same declared reviewer or
artifact cannot satisfy multiple lanes for a single lens. The queue does
not issue signatures, observe a screen, validate actual artifact bytes,
execute a native emulator, verify reviewer personhood, or prove independent
observations. Signed metadata is not scientific or production evidence.
All native, device, training, adversary and promotion claims remain held.
The source is bounded to 8 MiB and queue output is paginated.

Existing synthetic fixture tests and new full-catalogue and receipt-custody
regressions are selected in CI. Their execution remains unverified.
