# Jeeves — real local GGUF coding from a headless terminal

Jeeves now has a headless source-generation command that actually uses the
**existing installed local GGUF, isolated native child and principal-bound
SQLite chat**. This closes the operational gap between the Tk-only native
source-repair window and the separately implemented headless source reviewer.

This is not a second model, mock backend, cloud service, daemon, private
index, autonomous Git bot, code-execution environment or alternate inference
engine. The source is generated by the exact existing
`DesktopBridge → desktop_host → native GGUF → SQLite` path and admitted
by the exact existing `NativeSourceRepairRunner` before any deliverable
is described as reviewable.

## Command and two-phase operator consent

From an authorized checkout with the independently installed GGUF and
private state already provisioned, call:

```bash
# 1: inspect operator task and exact original project file hashes.
python -m skeleton.ai.runtime.operational_ai.laptop_runtime.desktop_native_code_cli \
  < /private/local/task-inspect.json

# 2: after reading the result and providing its exact digests,
#    approve one finite source-generation sequence.
python -m skeleton.ai.runtime.operational_ai.laptop_runtime.desktop_native_code_cli \
  --approve-native-generation < /private/local/task-approved.json

# 3: ONLY when explicitly authorized to disclose the generated source
#    in stdout (capture in private 0700 storage):
python -m skeleton.ai.runtime.operational_ai.laptop_runtime.desktop_native_code_cli \
  --approve-native-generation --emit-private-proposal \
  < /private/local/task-approved.json \
  > /private/local/generated-private-result.json
```

The thin `scripts/jeeves_native_code.py` launcher calls the same
library. No prompts, usernames, original source or installed model
paths belong in the operator process's argv. Model paths and human
goals are input exclusively through a single strict JSON stdin record.

**Important:** these three invocations are **alternatives**, not
sequential ways to repeat the same approved native task. The second
and third commands each start a distinct native/SQLite generation;
choose only one after inspecting the original task. Never repeat a
generation merely because its exit or stdout is uncertain—first
inspect the durable SQLite session/request IDs reported or recover
with the previously established explicit operator controls.

## Exact request schema

All fields are required. Unused `job_sha256` and
`source_context_sha256` initially use `null`.
Illustrative operator task:

```json
{
  "schema": "jeeves.desktop.headless-native-source-work.v1",
  "action": "inspect",
  "project_root": "/private/checked-project",
  "model_root": "/private/installed-approved-gguf",
  "state_dir": "/private/jeeves-sqlite",
  "tenant": "local",
  "subject": "operator",
  "goal": "Add a standalone helper module and update src/main.py to call it",
  "format": "mixed-work",
  "maximum_attempts": 2,
  "source_paths": ["src/main.py"],
  "source_context_sha256": null,
  "job_sha256": null,
  "context_tokens": 4096,
  "max_output_tokens": 1024,
  "threads": 4,
  "gpu_layers": 0,
  "inference_ms": 90000,
  "capacity_budget_bytes": 8000000000
}
```

Accepted `format` values are `new-files`,
`existing-edits` and `mixed-work`.
Existing-file editing is most reliable with **explicitly
selected original source files**. The headless inspector
allows up to four exact relative paths, rejects hidden
Git/workflow/secret material, and reuses the descriptor-rooted
original file reader (6 KiB per selected source, 8 KiB total).
No recursive repository scan or unsanctioned tool is added.

The **inspect** request never starts a model or opens SQLite.
It returns a public receipt with the full `job_sha256` binding
the selected task goal, identity, source paths, exact original
source-manifest SHA, operator-selected CPU/token budgets and
model/state/project root selection. It also reports each
selected original path's real SHA-256/byte count,
`native_gguf_started=false` and explicit release/device holds.
Original source text and private absolute paths are never
printed in the inspection receipt.

For **generate**, change exactly these fields:

- `action` to `generate`;
- `job_sha256` to the full 64-character job hash returned by
  the inspection;
- `source_context_sha256` to the full 64-character original
  source-context hash if any files were selected; otherwise
  leave it `null`.

All other task and resource fields must stay exactly as
inspected. The program reopens the original trusted source,
checks the source-manifest SHA and exact job SHA **before
starting any native process**. Changed source, a new task,
missing full hashes, altered budgets or a different
selected model/state/root are held without starting a model.

Then **`--approve-native-generation`** is required as an
independent, explicit command-line action. The JSON document
cannot smuggle an equivalent approval field.

## Actual native execution and guarded outcome

After both approvals, the command creates a `DesktopConfig`
with the same installed GGUF root, SQLite state and original
tenant/subject. It enables **live pressure supervision and the
fresh pre-activation CPU/RAM/cgroup/disk admission** before
loading model weights. It uses CPU-only by default: no
unsupported VRAM/GPU performance guess or silent reduction
of operator-selected context/output/thread budgets.

The isolated child publishes a source-bound `native-gguf-ready`
receipt tied to the installed model digest and source state.
The parent verifies that witness and opens **one new
principal-bound SQLite session**, then runs the existing finite
native source-repair pipeline (one to three distinct SQLite
committed requests).

Every model turn has a new exact request ID, answer SHA,
original model digest, principal-bound session and
authoritative-commit proof. A malformed JSON result, invalid
Python/JSON/TOML, impossible relative Python import or
mismatched existing-file SHA may receive a **new** bounded
repair turn, but an uncertain SQLite effect is never
silently replayed.

The runner rechecks any selected original source by actual
SHA-256/inode/mtime/ctime before and after native generation.
It then uses the existing strict new-file/edit/mixed
source-plan parser, descriptor-custody review, deterministic
Git patch generator, non-executing static source gate and
SHA-bound import graph.

A successful native result is **`review-required`**,
not **`ready-for-production`**: the source has passed its
bounded original source/structural gates but still requires
operator inspection and independent Git/build qualification.
The native child is closed after the action while preserving
the SQLite session ledger, even on a held outcome.

## Private result disclosure and the next delivery step

The normal `generate` receipt reports only committed
request IDs and hashes, model/session identifiers, attempt
status, source-plan/patch identities and qualification.
It does **not** include model-written source text.

Adding `--emit-private-proposal` permits the generated
`private_proposal` string to appear in stdout ONLY when
a source candidate successfully passed the exact original
review and the command is also explicitly approved for
native generation.

The field is **sensitive source**, not a separate write
authorization. Keep its captured output in owner-private
local storage; do not paste it into public Git/issues or
CI logs. To complete a real project change, extract that
original schema string into the earlier strict headless
source-work CLI's `mixed_work`, `new_files` or
`existing_edits` field and perform **another human
patch/source review**. That CLI independently reopens
the original source and returns fresh manifest/patch
SHA-256 values. Only after separately approving
both complete hashes can it export an inert Git patch
or place final source into a brand-new sealed private
staging directory.

No generated source is ever automatically applied to
the original checkout, executed, pushed to GitHub, merged
or released. All model-generated filenames/code remain
untrusted even if their syntax parses.

## Limits and safety

The input is one strict JSON message limited to 16 KiB,
with duplicate keys, unknown fields, nonfinite values,
invalid UTF-8, booleans masquerading as budgets,
unbounded task text and all GPU layer requests
rejected before native startup. Model output is bound
to the existing native repair 16 KiB proposal ceiling,
up to three operator-approved committed repair turns,
and the original output context/inference deadline.
The public output is limited to 64 KiB; stderr contains
only a generic hold category, never a private path,
original code or model prompt.

An inspected job SHA binds the exact task/resourcing
parameters, not the installed physical weight bytes:
the separate native startup independently verifies
the original installed model SHA and rights receipt.
Future real-device acceptance must prove the physical
model, CPU/GPU pressure and power behavior. This source
flow does **not** bypass the existing guarded model
source/rights installation requirement.

Source-only regression tests use a contract-matching
test worker for deterministic results and never claim
a real GGUF was executed by CI. Verified source contracts
are different from physical Windows 11/WSL2 device
acceptance, model ownership/licensing validation,
native throughput qualification, full application
build, and all exact-head security/release gates.

The release, device, rights, original model and
security holds remain in force.

## Private source handoff with no code on stdout

When generated source must be stored for later
operator review, prefer
`desktop_native_proposal_cli` rather than the
`--emit-private-proposal` source-stdout option.
It requires both `--approve-native-generation` and
`--approve-private-storage`, checks an existing
owner-private parent and a brand-new `*.source.json`
destination **before starting the model**, and
writes only the independently reviewed original
proposal as a private `0600` file. Cold verify
never repeats inference. Its stdout contains hashes,
not code. Full guide:
`docs/ai/JEEVES_NATIVE_PRIVATE_SOURCE_ESCROW.md`.
