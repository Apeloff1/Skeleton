# Dragon deep archive — scalable custody and retrieval

The 32 active and 128 cold chambers are working sets, not the deep archive ceiling. Deep custody uses 1,024 deterministic owner partitions of 1,024 reservations each, nominally 1,048,576 expeditions (hash skew and canonical storage admission can constrain actual capacity). Original Mongo rows remain authoritative, with reserve-before-release recovery and deterministic deletion cleanup. The compound catalogue index uses bounded keyset pages. A grant-bound, scope-hashed routing field uses at most 8,192 terms per expedition; exact source evidence is qualified before returning pointers. Approximate routing and page-local ranking are disclosed. No raw text is duplicated, no history becomes a current claim, and no source-use or model permission is expanded.

Common Crawl's October 2026 corpus contains 2.16 billion captures with separate WARC/WAT/WET and URL indexes: https://www.commoncrawl.org/blog/october-2026-crawl-archive-now-available ; https://www.commoncrawl.org/url-index. Dragon retains extracted text, not complete HTTP WARC responses. Independent object-store redundancy, raw WARC import/export, full-corpus ranking and distributed throughput qualification remain outstanding. The architectural reservation ceiling is not a measured dataset or load-test result.

### Integrated cold, deep, and HOAG Wiki retrieval

The cold working set now allows 1,024 retired expeditions, while deep custody has 1,024 partitions of 1,024 nominal reservations. Deep and cold indexed routes are separated; expiry removes derived keys, not source records. The native cockpit exposes deep promotion, cursor-paginated catalogue, finite archive rights, erasure and historical/current Wiki pointer lookup. WikiLibrarian produces request-local source pointers after original owner-authorized retrieval. Current Jeeves chat still receives live untrusted source passages via the established canonical context dependency path; historical pointers remain review-only, never silently granting inference authority. No external source prose is written into the shared HOAG atoms or distiller. Physical storage capacity and distributed throughput are unqualified.

### Archive sorting, filter binding and direct chat provenance

Historical Wiki queries now support a specific partition, every-term or any-term matching, relevance within indexed candidate pages, and cursor-stable global archive-admission time ordering. Temporal ordering is archive admission time, not an assertion of global source relevance or latest source validity. Keyset continuations bind owner scope, query, partition, match policy and sort; exact source matching rechecks all terms independently of the multikey index. Both concrete WikiLibrarian module paths now implement the bridge. Current canonical chat evidence receives a request-local Wiki provenance link only when its citation and exact passage digest match the live projection, without changing the source dependency's authority or retaining crawler prose in Wiki.
