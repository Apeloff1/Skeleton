# Emerald V7 — actual Three.js 0.186 joint/mixer evidence, not an approximate SLERP

The previously recorded **108/108** V7 crossfade samples were generated by an *offline approximation* of Three's animation mixer. Their zero additional intersections applied only to three anatomical pair types at those specific sampled instants. They do not prove that the renderer's actual action weights, loop wrapping or quaternion interpolation produce the same poses.

This branch introduces two independent, opt-in source tools to close that gap **without changing the installed Emerald V1/Hoarder, the V7 GLBs, crawling authority or user-visible runtime**.

## 1. Extract real Three AnimationMixer bone motion

`frontend/scripts/emerald-v7-three-mixer-trace.mjs` accepts the complete **SHA-256-verified original V7 GLB** on the operator's filesystem. It never instantiates the textures, browser canvas, WebGL renderer, external URL loading or crawler APIs. Instead it creates a separate 108-joint Three `Bone` hierarchy from the original glTF node transforms, reconstructs the exact 88 sampled animation channels per clip from the source BIN, and drives the actual **Three 0.186.1** `AnimationMixer` and `AnimationAction.crossFadeFrom(previous, 0.22, false)`. The source donor's root name includes spaces; internal bone identifiers are bound by stable joint index, without changing source geometry.

The verifier executes the same six transition directions previously tested, including `orbit-01 → orbit-02` and `orbit-02 → landing-1`. It records **nine actual mixer fade phases** per direction, action weights/playhead positions and every joint's local quaternion, local translation and 4×4 world transform. It does not author new animation tracks or change the original 160-key V7 correction.

```sh
cd frontend
node scripts/emerald-v7-three-mixer-trace.mjs \
  --stage pathfinder \
  --model /trusted/v7/pathfinder.glb \
  --samples 9 \
  --output /unused/evidence/pathfinder-three-mixer.json
node scripts/emerald-v7-three-mixer-trace.mjs \
  --stage archivist \
  --model /trusted/v7/archivist.glb \
  --samples 9 \
  --output /unused/evidence/archivist-three-mixer.json
```

The Node program requires the exact existing Three 0.186 revision and prevents changed GLB SHA, wrong stage, unsupported animation channels, bad hierarchy, nonfinite/unnormalized rotations, output overwrite and oversized trace emission.

## 2. Independently recompose bones, skin the mesh and check triangle contacts

`scripts/check_emerald_v7_three_mixer_trace.py` verifies the trace structure: exact GLB identities, Three version, all six distinct route directions, exact 108 sequential joints per pose, finite 4×4 matrices, joint quaternion norms, complementary fade weights and **no false GPU, full collision or release claims**. With `--model`, it also rechecks the full original binary's SHA itself. This is trace *consistency* evidence, not a proof that the JSON came from an unmodified runtime.

`scripts/qualify_emerald_v7_three_trace_contacts.py` then uses **the five original SHA-pinned reviewed geometry tools** and the real original V7 GLB to independently recompose the complete 108-node bone matrix hierarchy. It rejects discrepancies between those recomposed matrices and the actual Three trace. The resulting **365,997 posed vertices** enter the original exact triangle-distance contact engine, separately accounting for non-welded intersections, source-bind shared-index seam candidates and all pairs within an 8-mm margin. The scanner supports an atomic, exact-trace/SHA-pinned incomplete checkpoint for interrupted runs.

```sh
python scripts/check_emerald_v7_three_mixer_trace.py \
  --stage pathfinder --model /trusted/v7/pathfinder.glb \
  --trace /unused/evidence/pathfinder-three-mixer.json

python scripts/qualify_emerald_v7_three_trace_contacts.py \
  --stage pathfinder --model /trusted/v7/pathfinder.glb \
  --tools /trusted/sha-reviewed-contact-tools \
  --trace /unused/evidence/pathfinder-three-mixer.json \
  --checkpoint /unused/evidence/pathfinder-actual-three-checkpoint.json \
  --output /unused/evidence/pathfinder-actual-three-contacts.json
```

The same two commands must be run for Archivist with its own exact source and unused paths. A fully completed, measured **108-pose actual Three source-mixer contact run** is needed before claiming such qualification. No numbers from the earlier approximate 108-pose ledger may be silently reused as a Three-runtime result.

## Limits and acceptance

- The source tool uses the **real Three AnimationMixer**, but still simulates one fixed 0.22-second incoming-start/outgoing-end transition. It is not the actual browser renderer, arbitrary active loop phase, interrupted action chain or a physical GPU.
- The reviewed contact engine examines **only three** region pair types. Mixed-skin seam risk, unknown/adjacent regions, equipment, continuous-time swept geometry and per-frame driver scheduling remain unqualified.
- Neither trace extraction nor source-only CI reads from or writes to live crawler state, enables original equipment, re-pins original Hoarder, changes original V7 GLBs, installs a model or emits network telemetry.
- Source-only CI tests exact Three 0.186.1 against *synthetic fixture bones* and independently tests the matrix/trace rejection logic. It must not be counted as execution against the actual 229.5 MB V7 original model bytes.
- True artist-directed poster fidelity, human-authored original painted detail, Unreal compilation, physical RTX, release provenance and **the still-missing eight remote original Git binary objects** remain held.

All outputs mark `continuous_collision_qualified: false`, `physical_rtx_verified: false` and `release_qualified: false`. No automatic adoption, merge, release or installed-app update follows from the new trace.
