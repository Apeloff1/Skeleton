# Cinder Ridge — deterministic CAS journal and portable custody

`python -m skeleton.game.gameplay.ridge_rescue.journal_cli init --output initial.json` creates a source-bound initial save. `verify --journal initial.json` reports its exact head. `append --journal initial.json --expected HEAD --action '{"verb":"rest"}' --output next.json` checks the expected head, validates and replays all prior actions, applies one legal transition, then creates a new immutable save. A stale head or invalid action refuses publication. `fork --journal next.json --expected HEAD --sequence 0 --output fork.json` creates a verified historical fork without modifying the source branch. `export --journal next.json --output run.json` emits the portable full replay bundle; `import --bundle run.json --output restored.json` rebuilds the journal from verified gameplay.

Every entry carries a sequence, previous digest, action and SHA-256 digest over canonical data. The source world is embedded and digest-bound. Every load replays all actions and checks final state and chain head. This detects accidental corruption and ordinary tampering, **not authenticity against an attacker who controls the entire journal**. Use authenticated custody for multiplayer or cross-user trust. The local CLI uses create-only writes, does not overwrite, and does not claim full directory-anchored atomicity against hostile parent swaps.

The authored end-to-end acceptance source is separate from the exploratory source. `python -m skeleton.game.gameplay.ridge_rescue.cli demo --output rescue.json` performs genuine gathering, crafting, movement, rescue and earned protection; `verify --bundle rescue.json` replays that result. Regression tests cover successful protect/salvage, stale CAS, fork replay, rehashed forged outcomes, invalid actions, journal export/import, and CLI file no-overwrite.
