# passage_rerank — offline evidence capability

Deterministic diverse span reranking.

This is an existing-owner derived retrieval domain. No new provider, model,
credential, state authority, network service or game engine is created.
The source SHA, original bytes, tenant, subject and explicit rights approval
must arrive from independent controls. Dense vector input requires one exact
external embedding-model SHA; never fabricate dense evidence.

Mode: hybrid; context planning limit: 5632; byte ceiling:
71680; nominal latency budget: 43000ms; minimum
evidence: 2; priority: 8.

The 20 standard guarded operational boundaries are reused from the canonical
Python adapter implementation. This family adds explicit evidence entrypoints.
Operational boundaries: source, search, fusion, rank, context, plan, resource, schedule, permission, native, replay, memory, privacy, evaluate, audit, recover, stream, tool, checkpoint, health.

Fail-closed holds: hostile principal, source hash mismatch, unapproved source,
malformed Unicode, missing vector, model mismatch, resource overrun, invalid
citation or missing byte provenance. Text retrieval is never policy authority.

Run Python focused tests and all exact-final-head security/CI gates after
completing the whole dependency stack. This source casebook never proves
native GGUF quality, approved model rights or Windows/WSL2 device readiness.
