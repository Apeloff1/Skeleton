# memory_guard: bounded offline resource controls

Fail-closed memory headroom and slot pressure.

Exact model/tokenizer/tenant/subject scope is mandatory; short-lived capacity
observations and original source SHA cannot be manufactured by model text.
The authorized durable execution owner remains the existing SQLite work-order
and supervised GGUF spine, not the in-memory projection in this domain.

Policy context limit 10752 tokens; byte limit 73728;
nominal duration 29000ms; minimum evidence 4;
priority 6. The 20 canonical operators remain closed-source,
with a dedicated typed resource-control facade and focused regression suite.

Safety: reject bad scope, stale observation, missing observer attestation,
duplicate request ID, overbooking, stale CAS, ambiguous dispatch and unproved
native output. Never refund an effect that might have reached the native worker.
Commit charges actual authoritative tokens once; a replay cannot be counted as
new generation. Completion testing and target Windows device remain separate.
